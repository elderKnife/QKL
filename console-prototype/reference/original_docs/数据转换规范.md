# 数据转换规范（实验 A/B 共用）

## 1. 业务 JSON

字段名、数据类型、计量单位和时间格式全部固定，实验代码只允许使用下列 schema。

实验 A（运行数据）字段：

```json
{
  "recordId": "EDGE-PV-001",
  "deviceId": "PV-01",
  "deviceType": "photovoltaic",
  "metric": "active_power",
  "value": 45.6,
  "unit": "kW",
  "timestamp": "2026-10-24T13:00:00Z"
}
```

实验 B（调控指令）字段：

```json
{
  "commandId": "GRID-CMD-001",
  "deviceId": "BESS-01",
  "commandType": "storage_charge",
  "targetValue": 50.0,
  "unit": "kW",
  "timestamp": "2026-10-24T13:10:00Z",
  "nonce": "8 字节随机数，小写 hex"
}
```

时间格式：ISO-8601，统一 UTC，`YYYY-MM-DDTHH:MM:SSZ`。

## 2. 确定性 JSON 序列化

```python
json.dumps(obj, sort_keys=True, separators=(",", ":"), ensure_ascii=False)
```

规则：

- 键按字典序排序；
- 不含多余空白（`,` 与 `:` 直接连接）；
- 不转义非 ASCII 字符；
- 文本按 UTF-8 编码为字节。

同一 dict 在任何机器、任何时刻都会得到完全相同的字节序列。

## 3. 带域前缀的 SHA-256

叶子哈希：

```text
SHA256(b"FISCO-BCOS-EVIDENCE-LEAF-V1:" + utf8_bytes)
```

内部节点哈希：

```text
SHA256(b"FISCO-BCOS-EVIDENCE-NODE-V1:" + left_32bytes + right_32bytes)
```

域前缀用于消除“叶子与内部节点结构歧义”。本实验的 SHA-256 字节均可展示，输入预映像和输出摘要分别记录在 `merkle_inputs.json` 与 `single_record_trace.json` 中。

## 4. Merkle 树规则

- 记录排序：按 `recordId` 或 `commandId` 升序排序后编号；
- 左右子节点顺序：左侧 digest 在前，右侧 digest 在后；
- 奇数叶子处理：当前层最后一个节点不复制、不再哈希，直接提升到上一层；
- 证明格式：

```json
{
  "recordId": "EDGE-BESS-001",
  "position": 1,
  "proof": [
    {"side": "right", "hash": "..."},
    {"side": "left", "hash": "..."}
  ],
  "root": "..."
}
```

数据批次（实验 A）与指令批次（实验 B）复用同一 Merkle 计算模块 `src/merkle.py`。

## 5. 上链边界

智能合约只保存批次摘要与关联元数据：

- batchId、evidenceType、dataType；
- merkleRoot；
- recordCount；
- submitter、relatedBatchId；
- timestamp。

原始业务 JSON、单条 SHA-256、Merkle 证明均存放在链下 `output/<run_id>/`。

## 6. 必须区分的概念

- 原始 JSON：业务侧字段集合；
- 单条 SHA-256：某条 JSON 的带域前缀叶子摘要；
- Merkle 根：整批记录构成的树根摘要；
- ABI 编码的合约调用数据：以太坊风格 `selector + 参数编码`；
- 交易哈希：签名交易在链上的唯一标识。

并且：

- Merkle 成员证明只证明“某条记录属于某个摘要批次”，不能代替数据本身真实性的线下核验；
- 摘要存证只证明“某个摘要曾在链上登记”，不能等同于设备已实际执行该指令。
