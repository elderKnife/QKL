# 导师汇报说明：FISCO BCOS 可信存证与指令追溯最小可行实验

## 1. 研究目标

在真实运行的五节点 FISCO BCOS Air v3.16.4 PBFT 联盟链上，以最小开发成本验证两个技术路线：

- 分布式能源运行数据的可信存证；
- 电网调控指令的可信追溯。

本次只验证“真实上链、跨节点一致、Merkle 成员证明、篡改可发现”，不做性能测试、不开发前端、不追求生产级系统。

## 2. 系统架构

```text
EDGE ──原始JSON──> VPP_A ──Merkle根/元数据──> FISCO BCOS (chain0/group0, PBFT, 5节点)
                                                    |
GRID <──跨节点读取/重算根/核验────────────────────────┘

GRID ──业务签名JSON──> 链上指令批次根 ──> VPP_A 核验签名并写转发证据
                                                    |
EDGE <──核验签名/原始指令/Merkle证明/链上关联，模拟执行────┘
```

链：chain0、group0；共识：PBFT；节点：GRID、VPP_A、VPP_B、THIRD_A、THIRD_B；RPC 端口 20200–20204。

## 3. 数据转换过程

每条业务 JSON 按固定 schema 生成，使用确定性序列化和 UTF-8 编码，带域前缀 SHA-256 生成叶子哈希，再按固定排序和奇数提升规则生成 Merkle 根。智能合约只保存根和元数据，原文与证明在链下保存。详见 [数据转换规范](数据转换规范.md) 和 [单条样例完整过程](../output/experiment-A-20261024-135548-185731/single_record_trace.md)。

## 4. 实验 A：运行数据可信存证

EDGE 生成 3 条光伏/储能数据，VPP_A 计算批次根并真实上链，GRID 通过两个不同节点 RPC 端口读取同一根并重算核验，生成单条 Merkle 成员证明，篡改一条数据后证明失败且根不一致。

## 5. 实验 B：调控指令可信追溯

GRID 生成 3 条充/放电与光伏限发指令，使用独立业务 ECDSA 密钥对确定性字节签名并计算批次根上链；VPP_A 核验全部签名后写入关联原批次的转发证据；EDGE 核验签名、Merkle 证明和链上关联后模拟执行；篡改指令后签名验证失败且根不一致。

- 20200/20202 两节点查询一致
- 成员证明通过，篡改验证失败

## 7. 技术局限性

- 只验证最小业务闭环，未做并发、吞吐、时延或容错测试；
- 原始数据和证明在链下保存，链上只有摘要与元数据；
- 转发证据仅证明 VPP_A 对原指令批次的链上关联转发，不是设备实际执行的物理证明；
- 业务密钥仅用于演示来源签名，不涉及 PKI/证书体系。
