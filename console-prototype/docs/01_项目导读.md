# 项目导读
## 主文件与阅读顺序
1. contracts/EvidenceStore.sol：链上保存批次编号、类型、根、数量、submitter、关联批次和调用方时间戳。
2. src/common.py：路径/地址常量、确定性 JSON 字节、带域前缀的 SHA-256、辅助 ABI 选择器计算。
3. src/merkle.py：记录排序、构树、成员证明生成和验证；奇数末节点直接提升。
4. src/crypto_util.py：secp256k1 ECDSA、SHA-256；签名为固定 64 字节 r||s 的 hex。
5. src/chain.py：通过 Console/Java 子进程读写链。
6. src/experiment_a.py：三条运行数据的存证、一个成员证明和一个篡改样例。
7. src/experiment_b.py：三条指令签名、原文 Merkle 根、转发记录及模拟反馈。
8. src/run_all.py：按 A/B/all 选择流程；目前 pass=false 不会主动返回非零退出码。

src/outputs.py 创建输出目录并写 JSON/文本。
src/sample_trace.py 展示一条数据到哈希、证明、ABI 和历史交易 input 的转换，但运行入口含联网与文件写出。

## 当前流程与可信边界
A：同一进程产生样本 → 本地构树/重算 → 提交根 → 两端口查询 → 验一个成员证明 → 篡改演示。
B：同一进程生成或加载业务密钥 → 签三条指令 → 原文构树并提交 → 验签 → 提交关联转发 → 验一个证明 → 为三条指令生成模拟成功反馈。

GRID、VPP、EDGE 在这些脚本里主要是逻辑标签，并非独立服务。不同链 RPC 节点也不等于不同链上账户。
data/ 是参考样本；A/B 的主输入来自源码内置样本，不是直接读取这些文件。
历史通过结果支持小样本算法与调用演示，不支持独立主体可信闭环、全量异常定位或性能达标结论。
