## 4. 篡改演练

命令：`.venv/bin/python scripts/tamper_demo.py`
证据：`data/reports/tamper-BATCH-PKT-efd23c214ca645558db6.json`

| 步骤 | 结果 |
|---|---|
| 原始批次 | `VERIFIED` |
| 修改 1 条记录 `value`（+7.0） | `REJECTED` |
| 重算根 | 与链上根不一致 |
| 失败定位 | 仅被改的 `REC-RUN-AUTO-…-CP-102-…`（`ROOT_MISMATCH`） |
| 伪造 proof 方向 | `REJECTED` |
| 边缘包改一条记录后重发 | `SIGNATURE_INVALID`（HTTP 400） |
| 边缘包用未登记 keyId 重发 | `IDENTITY_NOT_ALLOWED`（HTTP 403） |

关键点：**链上根不变**，因此能证明“链下被改”而不是“链上被改”；
失败清单没有误报同包其它 9 条记录。

## 7. 已知问题与未完成项

| 编号 | 问题 | 影响 | 处理 |
|---|---|---|---|
| K1 | 官方 `build_chain.sh` 在 OpenSSL 4.x 下不兼容 | 建链失败/死循环 | 已在脚本中打 3 处补丁并注释，见 `docs/04` §2 |
| K2 | 官方 Python SDK 的 `utils/request.py` 使用不存在的 `response.cb_context` | 所有 RPC 调用失败 | vendored 副本改为返回 `response.content`（`PATCH(local)`） |
| K3 | SDK 依赖 `collections.Iterable` 等 Python 3.10 已移除的名字 | 导入失败 | `src/common/compat.py` 在导入前恢复别名，不改 vendored 源码 |
| K4 | 5 个共识节点在同一台机器 | 不能推断生产高可用 | 报告中明确标注 |
| K5 | 边缘与 VPP 之间无 TLS/认证网关 | 仅本机实验适用 | 跨机部署前必须补 |
| K6 | 私钥为测试身份，未接入 PKI/HSM | 仅实验 | `.gitignore` 排除 `config/keys/` |
| K7 | 设备数据由边缘模拟（A1 替身）或注入脚本产生 | 规模与真实性有限 | 接入 A1 后替换采集端 |
| K8 | 未做性能计时与并发压测 | 无性能结论 | 后续按任务书 §8 单独开展 |
| K9 | 链为 2.11.0（非 3.x） | 版本较旧 | 已在 `docs/04` §1 说明原因 |
| K10 | 指令闭环为同步调用 | 长事务、无重试队列 | 仅本机演示；生产需异步任务与超时补偿 |
| K11 | 未做并发重复指令压测 | 不知道高并发下是否严格一次 | 后续补 A13 压测 |
