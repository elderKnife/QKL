# 03 数据协议（本轮冻结版本）

本文件是本实验的接口与密码学契约基线。版本号一旦变化，必须同时更新测试向量与证据，
不能让新算法静默解释旧证据。

| 版本标识 | 作用范围 |
|---|---|
| `DEVICE-RECORD-V1` | 设备记录 |
| `EDGE-PACKET-V1` | 边缘包 |
| `VPP-BATCH-V1` | VPP 批次 envelope |
| `CANON-JSON-V1` | 规范化 JSON 字节规则 |
| `MERKLE-V1` | 叶子/节点哈希与奇数提升规则 |
| `BUSINESS-SIG-V1` | ECDSA secp256k1 + SHA-256 + `r‖s` |

## 1. 设备记录 `DEVICE-RECORD-V1`

```json
{
  "recordId": "REC-RUN-MINI-001-121647-PV-101-001",
  "deviceId": "PV-101",
  "deviceType": "pv",
  "metric": "active_power_kw",
  "value": 12.345,
  "unit": "kW",
  "timestamp": "2026-11-04T12:16:47.123Z"
}
```

规则：

- 七个字段必填，**不接受额外字段**；
- `recordId`/`deviceId`：`^[A-Za-z0-9][A-Za-z0-9._:-]{0,127}$`；
- `deviceType ∈ {pv, storage, charger}`；`metric = active_power_kw`；`unit = kW`；
- `value` 是 **JSON number**（不是字符串），必须是有限值且最多 3 位小数；
  `pv`/`charger` 不允许负数（`storage` 正=放电、负=充电）；
- `timestamp`：UTC ISO-8601，**必须带毫秒和 Z**：`YYYY-MM-DDTHH:MM:SS.sssZ`。

## 2. 边缘包 `EDGE-PACKET-V1`

```json
{
  "schemaVersion": "EDGE-PACKET-V1",
  "packetId": "PKT-…",
  "edgeId": "edge-01",
  "collectedAt": "2026-11-04T12:16:47.456Z",
  "records": [ {…}, {…} ]
}
```

- 包原文**不含签名**；签名作为外部证据单独传输：

```json
{
  "algorithm": "ECDSA-secp256k1-SHA256",
  "ruleVersion": "BUSINESS-SIG-V1",
  "keyId": "edge-01-key-v1",
  "value": "<128 hex chars>"
}
```

- 签名覆盖 `CANON-JSON-V1(包原文)` 的 SHA-256；
- 记录在成包前按 `(deviceId, timestamp, recordId)` 排序；该顺序是包原文的一部分；
- VPP 只接受 `config/system.json` 中 `trustedEdges[edgeId].publicKey` 验证通过的包，
  **不接受包内自带公钥**；
- 同一 `packetId` 重试必须复用同一原文与签名。

## 3. 批次 envelope `VPP-BATCH-V1`

```json
{
  "schemaVersion": "VPP-BATCH-V1",
  "batchId": "BATCH-PKT-…",
  "vppId": "vpp-a",
  "edgeId": "edge-01",
  "packetId": "PKT-…",
  "recordCount": 5,
  "rootHash": "<64 hex>",
  "builtAt": "2026-11-04T12:16:47.789Z",
  "merkleRuleVersion": "MERKLE-V1",
  "canonicalRuleVersion": "CANON-JSON-V1",
  "records": [ … ],
  "proofs": [ … ],
  "chainReceipt": {
    "txHash": "0x…",
    "blockNumber": 10,
    "registryAddress": "0x84a6…",
    "status": "CONFIRMED"
  }
}
```

- `batchId = "BATCH-" + packetId`（一条边缘包一个批次）；
- `proofs` 与 `records` 一一对应，每个 proof：

```json
{
  "ruleVersion": "MERKLE-V1",
  "batchId": "BATCH-…",
  "recordId": "REC-…",
  "index": 0,
  "treeSize": 5,
  "siblings": [{"hash": "<64 hex>", "position": "left"|"right"}]
}
```

- VPP 用 `BUSINESS-SIG-V1` 对整个 envelope（含 `chainReceipt`）签名后发给 GRID；
- GRID 不使用 envelope 自报的 `rootHash` 作为信任来源，而是用链上读到的根。

## 4. 规范化规则 `CANON-JSON-V1`

本规则是**项目自己的**确定性 JSON 规则，不宣称等同 RFC 8785。

1. 对象键按 Unicode 码点升序；
2. 分隔符固定为 `,` 与 `:`，无多余空白；
3. 字符串 UTF-8、`ensure_ascii=false`，并做 NFC 规范化；
4. 数字用十进制最短表示，禁止科学计数法；拒绝 NaN/Infinity；
5. 布尔与 null 原样；不接受空键；重复键（解析时）直接拒绝；
6. 输出结尾无换行。

实现：`src/common/canonical.py`；测试：`tests/test_canonical.py`。

## 5. Merkle 规则 `MERKLE-V1`

沿用任务书 §6.2 的历史前缀，保证旧证据语义不被改写：

```
leaf = SHA256(b"FISCO-BCOS-EVIDENCE-LEAF-V1:" + CANON-JSON-V1(record))
node = SHA256(b"FISCO-BCOS-EVIDENCE-NODE-V1:" + left_digest ‖ right_digest)
```

- 子摘要以 **32 字节原值** 拼接，不转 hex 文本；
- 叶子顺序：`(deviceId, timestamp, recordId)` 升序；
- 奇数层最后节点**直接提升**（不自我复制）；
- 空集合、重复 recordId、非法字段在构树前拒绝；
- 单叶树根 = 叶哈希，证明路径为空且必须可验证；
- 验证时检查：版本、索引范围、路径长度、兄弟方向与提升规则的一致性；
  最后与**外部提供的 expectedRoot** 比对。

固定在 `tests/test_merkle.py` 覆盖 1/2/3/5/6/7/8/30/31/33 条。

## 6. 业务签名 `BUSINESS-SIG-V1`

| 项 | 规则 |
|---|---|
| 曲线 | secp256k1 |
| 摘要 | SHA-256 |
| 签名编码 | 固定 64 字节 `r‖s` 的 128 位 hex，非 DER、无 recovery id |
| 公钥编码 | 非压缩 65 字节（`04‖X‖Y`），130 位 hex |
| 私钥文件 | PEM，权限必须 0600，缺失或权限过宽直接报错 |
| 签名确定性 | RFC6979（`ecdsa` 库 `sign_digest_deterministic`） |

## 6.5 指令 `GRID-COMMAND-V1` 与回执 `EDGE-ACK-V1`

### 命令对象

```json
{
  "schemaVersion": "GRID-COMMAND-V1",
  "commandId": "CMD-…",
  "gridId": "grid",
  "targetEdgeId": "edge-01",
  "targetDeviceId": "PV-101",
  "action": "set_voltage",
  "params": {"voltageV": 230.5},
  "issuedAt": "2026-11-04T13:42:43.427Z",
  "expiresAt": "2026-11-04T13:44:43.427Z",
  "nonce": "…"
}
```

| 字段 | 约束 |
|---|---|
| `action` | `set_voltage` / `power_on` / `power_off` |
| `params` | `set_voltage` 必须且只能有 `voltageV`（number，180–260，最多 1 位小数）；开/关机必须为 `{}` |
| `expiresAt` | 必须晚于 `issuedAt`，TTL ≤ 600 秒（本实验默认 120 秒） |
| `targetEdgeId`/`targetDeviceId` | 必须属于同一边缘；VPP 还会校验该边缘归自己服务 |

命令由 GRID 签名；签名规则同 `BUSINESS-SIG-V1`。链上锚定：

```
batchId = BATCH-CMD-<commandId>
root    = SHA256(LEAF_PREFIX + CANON-JSON-V1(command))
count   = 1，vppId = "grid"，schemaVersion = "GRID-COMMAND-V1"
```

### 回执对象

```json
{
  "schemaVersion": "EDGE-ACK-V1",
  "ackId": "ACK-…",
  "commandId": "CMD-…",
  "commandDigest": "<命令规范化字节的 SHA-256>",
  "edgeId": "edge-01",
  "deviceId": "PV-101",
  "action": "set_voltage",
  "result": "APPLIED",
  "appliedState": {"on": true, "voltageV": 230.5},
  "executedAt": "2026-11-04T13:42:44.465Z"
}
```

边缘签名回执；VPP 校验后锚定：

```
batchId = BATCH-ACK-<ackId>
root    = SHA256(LEAF_PREFIX + CANON-JSON-V1(ack))
count   = 1，vppId = 当前 VPP，schemaVersion = "EDGE-ACK-V1"
```

### 回执 envelope（VPP → GRID）

```json
{
  "schemaVersion": "ACK-ENVELOPE-V1",
  "vppId": "vpp-a",
  "ack": {…},
  "command": {…},
  "edgeSignature": {…},
  "chainReceipt": {"txHash": "0x…", "blockNumber": 95, "registryAddress": "0x…", "status": "CONFIRMED"},
  "builtAt": "…"
}
```

GRID 校验 VPP 签名后，重新计算 ack 根、命令根，并分别与链上 `BATCH-ACK-*`、`BATCH-CMD-*` 比对；
全部一致才把命令置为 `COMPLETED`。

## 7. 链上合约 `RootHashRegistry`

Solidity 0.6.10，ABI：

| 方法 | 参数 | 返回 |
|---|---|---|
| `registerBatch` | `string batchId, bytes32 root, uint64 recordCount, uint64 submittedAt, string vppId, string schemaVersion` | `bool` |
| `getBatch` | `string batchId` | `(bool exists, bytes32 root, uint64 count, uint64 submittedAt, string vppId, string schemaVersion)` |
| `existsOf` | `string batchId` | `bool` |
| `setAuthorized` | `address account, bool allowed` | —（仅 owner） |
| `owner` / `authorized` | — / `address` | `address` / `bool` |

写入规则：

- `batchId` 非空且 ≤128 字节；`root != 0`；`recordCount > 0`；
- `batchId` 已存在 → revert `BATCH_EXISTS`（不可静默覆盖）；
- 仅 `authorized[msg.sender]` 可写；owner 可授权。

**链上不保存 records、proofs、原始包或设备明细。**

## 9. 错误码与 HTTP 映射

| 错误码 | HTTP | 含义 |
|---|---|---|
| `INVALID_SCHEMA` | 400 | 字段/类型/精度/时间格式错误 |
| `DUPLICATE_ID` | 409 | 记录编号重复 |
| `IDEMPOTENCY_CONFLICT` | 409 | 同编号不同内容 |
| `IDENTITY_NOT_ALLOWED` | 403 | 未登记主体或 keyId 不匹配 |

所有错误体：

```json
{"error": {"code": "…", "message": "…", "objectId": "…", "retryable": false}}
```

## 10. 状态枚举

| 层 | 状态 |
|---|---|
| 边缘投递 | `BUILT` → `DELIVERED` / `DUPLICATE_AT_VPP` / `DELIVERY_FAILED` |
| VPP 批次 | `RECEIVED` → `MERKLE_BUILT` → `CONFIRMED` / `FAILED` / `UNKNOWN` / `CHAIN_UNAVAILABLE`，转发后 `FORWARDED` / `FORWARD_FAILED` |
| GRID | `VERIFIED` / `REJECTED`（附 `checks` 与 `failures`） |
