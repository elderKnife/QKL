# QKL V2：在另一台电脑部署

本文是当前 V2 的全新安装指南。拓扑为 3 个 VPP、30 个边缘、900 台模拟设备和 1 个 GRID；底层是 FISCO BCOS **2.11.0** 的 5 节点 PBFT 链。数据内容走本机 HTTP，链上只存根和必要元数据。GRID 指令每次只针对一个 VPP，核验成功由 VPP 直接返回，暂不下发到边缘执行。

给 AI 的完整任务和验收要求见根目录 [AI_DEPLOY.md](../AI_DEPLOY.md)。已有部署只需日常启动时，见 [START.md](../START.md)，不要重新生成密钥或重建链。

## 1. 环境要求

| 项目 | 要求 / 说明 |
|---|---|
| 操作系统 | 已验证 macOS Apple Silicon；macOS Intel、Linux x86_64 / ARM64 提供安装路径，但没有在这些平台完成全量实测 |
| Windows | 使用 WSL2 Ubuntu，在 Linux 文件系统中克隆和运行；不使用原生 PowerShell 执行 bash 脚本 |
| Python | 推荐 **3.10**，当前完整测试版本 3.10.11；3.11 及更新版本未完成兼容性验证 |
| Node.js / npm | 推荐 Node.js **22.12+ 的 22.x LTS**；Vite 7 最低要求 20.19+ 或 22.12+。npm 随 Node 安装，使用 `npm ci` |
| Bash | **5+**，特别是建链脚本；macOS 系统 `/bin/bash` 3.2 不适用 |
| OpenSSL | OpenSSL 1.0.2 / 1.1 / 3.x / 4.x；本机已验证 4.1，使用仓库内兼容补丁后的建链脚本 |
| 系统命令 | `git`、`curl`、`tar`、`xxd`、`ps`、`pgrep`、`pkill`；Python 构建依赖可能需要 C/C++ 编译工具 |
| 区块链 / 编译器 | FISCO BCOS **2.11.0**，ECDSA / 非国密；Solidity **0.6.10**，推荐下文固定版本的 solc-js，ARM 上无需 Rosetta |
| 资源 | 建议 4 核、8 GB 内存、10 GB 可用空间起步，随链和实验历史增长；这是实验建议，不是测得的最低配置 |
| 网络 | 初次需要访问 GitHub Releases、Python 包源和 npm；应用运行后只使用本机回环网络 |

只需要 Python + Vue + FISCO。`console-prototype/` 下还保留旧 Go / MySQL / Docker 原型，当前 V2 **不从 compose.yaml 启动**，也不需要安装 MySQL、Redis、Go 或 Docker。

macOS 可先安装：

```bash
brew install python@3.10 node@22 bash openssl@3
export PATH="$(brew --prefix node@22)/bin:$(brew --prefix openssl@3)/bin:$PATH"
```

需有 Xcode Command Line Tools；缺少编译器时用 `xcode-select --install` 安装。Linux / WSL2 安装发行版的 `git curl openssl xxd build-essential libssl-dev libffi-dev`，并安装可创建 venv 的 Python 3.10 和 Node.js 22。不要为本项目替换系统 Python。先检查 `python3.10 --version`、`node --version`、`npm --version`、`bash --version`、`openssl version`。

## 2. 克隆与 Python 初始化

在希望放项目的位置运行，后续命令均以仓库根目录为工作目录，不依赖作者的绝对路径：

```bash
git clone https://github.com/elderKnife/QKL.git
cd QKL
python3.10 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements-lock.txt
.venv/bin/python scripts/prepare_local.py
.venv/bin/python scripts/configure_v2.py
.venv/bin/python scripts/gen_accounts.py
```

`requirements-lock.txt` 是通过测试的 Python 环境版本快照；`requirements.txt` 保留直接依赖范围。某系统/架构没有相应 wheel 时先补齐构建工具；若确需改用 `requirements.txt`，需重新测试并记录实际版本，不能直接声称复现相同环境。

`prepare_local.py` 从 SDK 模板创建 `vendor/python-sdk/client_config.py`，并建立日志目录，是新克隆必需步骤；现有文件会保留。无需安装另一个同名 `client` / `web3` 包，不运行 SDK 的 `init_env.sh` 替换本项目依赖。

`gen_accounts.py` 生成本机 34 个测试身份：GRID 1、VPP 3、边缘 30，同时更新 `config/system.json` 的公钥和账户地址。PEM 权限应为 `600`。普通重跑保留密钥；`--force` 会让已有链绑定和签名证据失配，日常部署不要使用。

## 3. 下载本平台 FISCO 二进制

只执行与你的平台对应的一项，然后执行公共下载命令：

```bash
# macOS Apple Silicon
QKL_FISCO_ASSET=fisco-bcos-macOS-aarch64.tar.gz
# macOS Intel 则使用：QKL_FISCO_ASSET=fisco-bcos-macOS.tar.gz
# Linux / WSL2 x86_64：QKL_FISCO_ASSET=fisco-bcos.tar.gz
# Linux ARM64：QKL_FISCO_ASSET=fisco-bcos-aarch64.tar.gz

mkdir -p chain/bin
QKL_FISCO_TMP=$(mktemp -d)
curl -fL --retry 3 \
  "https://github.com/FISCO-BCOS/FISCO-BCOS/releases/download/v2.11.0/$QKL_FISCO_ASSET" \
  -o "$QKL_FISCO_TMP/fisco.tar.gz"
tar -xzf "$QKL_FISCO_TMP/fisco.tar.gz" -C chain/bin
chmod +x chain/bin/fisco-bcos
chain/bin/fisco-bcos --version
```

必须看到 2.11.0。`Exec format error` / `Bad CPU type` 通常是架构错误。下载失败先确认网络或代理，不把 HTML 错误页当作二进制运行，也不自动改用来源不明的镜像。保留临时目录便于排错。

## 4. 编译合约

推荐跨平台方式（不安装全局 npm 包）：

```bash
npm install --prefix tools/solcjs --no-save --no-audit --no-fund solc@0.6.10
./scripts/compile_contract.sh
```

若 `tools/solc` 是已存在且可运行的 0.6.10 原生编译器，脚本优先使用它；否则使用 `tools/solcjs`。已有错误版本会报错，不悄悄换编译器。两条路径均生成：

```text
contracts/build/RootHashRegistry.abi
contracts/build/RootHashRegistry.bin
contracts/build/RootHashRegistryV2.abi
contracts/build/RootHashRegistryV2.bin
```

当前部署的是 `RootHashRegistryV2`；保留 V1 产物供历史代码和测试使用。全新安装不执行 `deploy_contract.py`。

## 5. 建立并启动 5 节点链

先确认端口空闲：业务 `8101–8130`、`8201–8203`、`8301`、`8400`；链 RPC `8545–8549`、P2P `30300–30304`、Channel `20200–20204`。已占用时先辨认进程和已有部署，不盲目结束其他应用。

以下建链命令只用于**新电脑、尚无 `chain/nodes/` 的第一次部署**。有历史时不重复建链。

macOS（Homebrew 自动区分 Intel / Apple Silicon 路径）：

```bash
QKL_BASH="$(brew --prefix bash)/bin/bash"
(
  cd chain
  "$QKL_BASH" build_chain.sh -l 127.0.0.1:5 -p 30300,20200,8545 \
    -v 2.11.0 -c pbft -C 1 -e ./bin/fisco-bcos -o ./nodes
)
./scripts/start_chain.sh
```

Linux / WSL2（确认 `bash --version` 为 5+）：

```bash
(
  cd chain
  bash build_chain.sh -l 127.0.0.1:5 -p 30300,20200,8545 \
    -v 2.11.0 -c pbft -C 1 -e ./bin/fisco-bcos -o ./nodes
)
./scripts/start_chain.sh
```

使用仓库里的 `chain/build_chain.sh`，不以原版覆盖兼容补丁。不加国密参数 `-g`，不改用 FISCO 3.x。应生成 `chain/nodes/127.0.0.1/node0..4/`，五个 RPC 都返回区块高度。

## 6. 部署本机合约并绑定身份

```bash
.venv/bin/python scripts/deploy_v2.py
```

首次部署新合约、发送 34 个身份授权交易，写入本机 `config/chain-v2.json`，通常需要等待几十秒，以实际链速度为准。文件不入 Git；每台独立新链都要本地生成。

已有文件时脚本保留它，不自动覆盖。若提示已部署但服务失败，先查 RPC、合约代码和账户绑定，不能把旧文件当成功证明。不要复制作者地址或手填地址跳过部署。`config/chain.json` / `config/legacy/` 是 V1 历史配置，不供 V2 读取。

## 7. 构建前端并启动服务

```bash
npm ci --prefix console-prototype/frontend
npm run build --prefix console-prototype/frontend
./scripts/start_services.sh
.venv/bin/python scripts/check_deployment.py
```

启动器应报告 **35 个业务服务健康**；自检还确认五节点看到相同的五个共识身份、本机合约在各 RPC 有代码、34 个发布者绑定正确、前端已构建。自检只读，不产生交易，不能代替下面的端到端验真。

打开 [http://127.0.0.1:8400/](http://127.0.0.1:8400/)：

| 角色 | 用户名 | 密码 |
|---|---|---|
| GRID | `grid` | `grid-local-password` |
| VPP | `vpp` | `vpp-local-password` |

35 个服务 = 30 边缘 + 3 VPP + GRID + Vue 控制台后端。使用本机演示账户和回环地址；本指南不自动暴露公网端口。

## 8. 验收功能

1. GRID 登录看到三个 VPP / 30 个边缘 / 900 台设备。VPP 登录可切换三个 VPP，指令发布和 GRID 手动批量校验只给 GRID。
2. 选择一个 VPP，单轮采样后 GRID 得到 300 条数据并自动验真成功。详情有 10 个边缘组各 30 条；连续采集首次约 2 秒产生一轮，随后每 30 秒一轮，可暂停。
3. 「指令下发」选 VPP、边缘和设备发单条指令；VPP 独立读链验真并返回成功，核对交易、根和目标。
4. 同一 VPP 下多选边缘和设备，批量只有一个上链根。切换 VPP 清空清单，后端拒绝跨 VPP 请求。
5. 发布时间到秒，指令成功接收时间到毫秒；时延单位 ms。批量指令/12000 条数据的主要验证耗时只计最终根相等比较，重算、读链和传输排除，发布总耗时另列。极短比较保留六位小数，不代表完整处理时间。
6. 完整 40 批实验先暂停全部采集，再执行：

```bash
.venv/bin/python scripts/experiment_v2.py --vpp vpp-a
# 或三个 VPP 都跑：.venv/bin/python scripts/experiment_v2.py
```

仍使用真实 FISCO 交易和 HTTP，通过手动采样加速；应生成 40 批 / 12000 条聚合组并通过 GRID 重算核验，报告在 `data/reports/v2/experiment.json`。正常 30 秒采集自然积累 40 批约需 20 分钟。GRID 数据上传成功向 VPP 返回 HTTP 204 空响应，指令核验成功返回是另一个流程。

自动化检查：

```bash
.venv/bin/python -m unittest discover -s tests -q
npm run build --prefix console-prototype/frontend
```

单元测试的链替身不代表真实链已跑通。需浏览器集成测试时，先跑完整三个 VPP 的 40 批实验，再执行：

```bash
cd console-prototype/frontend
npx playwright install chromium
WEB_BASE_URL=http://127.0.0.1:8400 npm run test:e2e
```

Linux 缺浏览器系统依赖时按 Playwright 提示安装。已装 Chrome 可设置 `PLAYWRIGHT_EXECUTABLE_PATH` 为该电脑真实路径。当前有 5 项 UI 测试，会重验聚合组并生成测试指令交易，是附加验收，不是日常启动前提。

## 9. 日常重启、更新与排错

日常在仓库根目录运行 `./scripts/start_chain.sh`、`./scripts/start_services.sh`，启动后自动采集默认暂停。业务已运行时先 `./scripts/stop_services.sh`；停链用 `./scripts/stop_chain.sh`，均不清空数据。前端更新后重建，后端更新后重启业务。

`config/keys/`、`config/chain-v2.json`、`chain/nodes/`、`data/v2/` 是配套状态，保留历史时一起备份。不得只删一项继续旧会话。旧 `reset_local_state.sh`、`demo_flow.py`、`tamper_demo.py`、`chain_evidence.py` 属于 V1，不作为当前 V2 安装或验收步骤。

| 现象 | 排查 |
|---|---|
| `No module named client_config` | 运行 `.venv/bin/python scripts/prepare_local.py` |
| SDK 或其他 Python 导入失败 | 使用项目 `.venv/bin/python`、Python 3.10、锁定依赖和仓库内 SDK |
| 原生扩展安装失败 | 补齐编译工具/对应架构 wheel，检查 Python 版本，不无提示换版本 |
| 建链 Bash 报错或卡在密钥生成 | 用 Homebrew Bash 5、正确 OpenSSL 路径和仓库建链脚本 |
| solc 缺失或 ARM 无法运行 | 安装 `tools/solcjs` 的 0.6.10，不用其他平台二进制 |
| `no deployed registry address` | 先起五节点再运行 `deploy_v2.py`，检查本机证据 |
| 部署文件存在但无合约 / 绑定失配 | 检查是否换链/密钥，先备份配套状态，不强制覆盖 |
| 业务启动失败 | 读 `logs/services/<角色>.log`、`logs/sdk/`，查端口、PEM 权限、产物和链 RPC |
| 8400 错误或旧页面 | 构建 Vue，确认起当前 Python V2 控制台并刷新，不误起旧 Docker 原型 |
| 没有 12000 条可校验 | 先在同一 VPP、同一会话生成 40 个完整批次；启动不自动产生历史数据 |
| 时延很小 | 主指标仅根比较，详情的完整处理和发布总耗时含义不同 |

协议和计时规则见 [10-V2三级数据验真.md](10-V2三级数据验真.md)。
