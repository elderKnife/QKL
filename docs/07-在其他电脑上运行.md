# 07 在另一台电脑上运行

本文给出从零到可访问 Web 面板的完整步骤。仓库里**不包含**私钥、链节点数据、
大体积二进制和编译产物，需要在新机器上生成/下载。

## 0. 支持情况

| 平台 | 状态 | 说明 |
|---|---|---|
| macOS Apple Silicon（M 系列） | ✅ 已验证 | 本仓库开发环境（M4 / macOS 15.2） |
| macOS Intel | ⚠️ 理论可行 | 换用 `fisco-bcos-macOS.tar.gz`（x86_64） |
| Linux x86_64 | ⚠️ 理论可行 | FISCO 与 solc 都有 x86_64 版本 |
| Linux arm64 | ⚠️ 链可跑，编译需替代方案 | FISCO 有 aarch64；solc 0.6.10 无 arm64，需 solcjs/Docker |
| Windows | ❌ 不推荐 | 脚本是 bash，建议 WSL2 |

下面命令以 **macOS arm64** 为主，其他平台在对应步骤给出替换项。

## 1. 依赖清单

| 依赖 | 版本 | 用途 |
|---|---|---|
| Python | 3.10+ | 业务服务（本仓库在 3.10.11 验证） |
| Bash | 5.x | `build_chain.sh`（macOS 自带 3.2 会死循环） |
| OpenSSL | 任意（脚本已兼容 4.x） | 生成节点证书 |
| `xxd` | 系统自带 | 节点 ID 提取 |
| FISCO BCOS | 2.11.0 | 5 节点链 |
| solc | 0.6.10 | 编译 `RootHashRegistry.sol` |
| Node.js | ≥18 | 构建控制台 Vue 前端（`console-prototype/frontend`） |

macOS 安装 bash 5：

```bash
brew install bash
/opt/homebrew/bin/bash --version
```

## 2. 克隆仓库

```bash
git clone https://github.com/elderKnife/QKL.git
cd QKL
```

> 国内网络如果 `github.com` 不通，可临时把下载地址前缀换成 `https://gh-proxy.com/https://github.com/...`
> （本仓库在这台机器上就是这样下载 FISCO 与 solc 的）。`git clone` 也可以走 SSH：
> `git clone git@github.com:elderKnife/QKL.git`。

## 3. Python 环境

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -V          # 必须是 3.10+

# 构建控制台前端（dist 不入库）
cd console-prototype/frontend
npm ci
npx vite build
cd ../..
```

## 4. 生成测试身份

```bash
.venv/bin/python scripts/gen_accounts.py
```

会生成（均不入库）：

- `config/keys/{grid,vpp-a,vpp-b,edge-01..04}.pem`
- 并自动更新 `config/system.json` 里对应的公钥

> 这些都是**实验专用身份**，不要用于任何真实系统。

## 5. 下载两个二进制

### macOS Apple Silicon

```bash
mkdir -p chain/bin tools

# FISCO BCOS 2.11.0（macOS arm64）
curl -L -o /tmp/fisco.tgz \
  https://github.com/FISCO-BCOS/FISCO-BCOS/releases/download/v2.11.0/fisco-bcos-macOS-aarch64.tar.gz
tar xzf /tmp/fisco.tgz -C chain/bin
chmod +x chain/bin/fisco-bcos

# solc 0.6.10（x86_64，靠 Rosetta 运行）
curl -L -o tools/solc \
  https://github.com/ethereum/solidity/releases/download/v0.6.10/solc-macos
chmod +x tools/solc
```

没装 Rosetta 的话先执行：`softwareupdate --install-rosetta`。

### macOS Intel

```bash
curl -L -o /tmp/fisco.tgz \
  https://github.com/FISCO-BCOS/FISCO-BCOS/releases/download/v2.11.0/fisco-bcos-macOS.tar.gz
```

### Linux x86_64

```bash
curl -L -o /tmp/fisco.tgz \
  https://github.com/FISCO-BCOS/FISCO-BCOS/releases/download/v2.11.0/fisco-bcos.tar.gz
tar xzf /tmp/fisco.tgz -C chain/bin
chmod +x chain/bin/fisco-bcos

curl -L -o tools/solc \
  https://github.com/ethereum/solidity/releases/download/v0.6.10/solc-static-linux
chmod +x tools/solc
```

### Linux arm64

FISCO 用 `fisco-bcos-aarch64.tar.gz`；solc 0.6.10 没有 arm64 二进制，二选一：

- 用 x86_64 容器跑编译，把产物拷回 `contracts/build/`；
- 或用 solcjs：`npm i -g solc@0.6.10`，执行
  `solcjs --bin --abi -o contracts/build contracts/RootHashRegistry.sol`，
  再把生成的 `RootHashRegistry_sol_RootHashRegistry.bin/.abi` 重命名为
  `RootHashRegistry.bin/.abi`。

验证：

```bash
chain/bin/fisco-bcos --version    # 应显示 2.11.0
tools/solc --version              # 应显示 0.6.10
```

## 6. 编译合约

```bash
./scripts/compile_contract.sh
ls contracts/build/               # RootHashRegistry.abi / .bin
```

## 7. 建链并启动 5 个节点

```bash
cd chain
bash build_chain.sh -l 127.0.0.1:5 -p 30300,20200,8545 \
  -e ./bin/fisco-bcos -o ./nodes
cd ..
./scripts/start_chain.sh
```

macOS 必须用 bash 5：

```bash
/opt/homebrew/bin/bash build_chain.sh -l 127.0.0.1:5 -p 30300,20200,8545 \
  -e ./bin/fisco-bcos -o ./nodes
```

> 仓库中的 `chain/build_chain.sh` 已针对 OpenSSL 4.x 打过 3 处补丁
> （详见 `docs/04` §2），**不要**用上游原版直接覆盖，否则会卡在证书生成。

成功标志：`./scripts/start_chain.sh` 打印 5 个节点的 `getBlockNumber` 响应。

## 8. 部署合约

```bash
.venv/bin/python scripts/deploy_contract.py
```

输出合约地址、部署交易、VPP 授权交易，并写入 `config/chain.json`。
**每台机器都要重新部署**：仓库里提交的 `config/chain.json` 指向的是原机器的链，
在你自己的链上不存在那个地址。

## 9. 启动 8 个服务

```bash
./scripts/start_services.sh
```

会启动：

| 服务 | 端口 |
|---|---|
| edge-01..04 | 8101–8104 |
| vpp-a / vpp-b | 8201 / 8202 |
| grid | 8301 |
| FISCO 控制台 | 8400 |
| FISCO node0..4 | 8545–8549 |

全部健康检查通过后，浏览器打开：

**http://127.0.0.1:8400**

登录账号：VPP `vpp / vpp-local-password`；GRID `grid / grid-local-password`。
进入「实验控制」点「开始连续采集」即可看到每 10 秒自动采集；
批次详情里的「日志」按钮可展开链上账本、证书、哈希和交易回执。

## 11. 与“原机器”的差异

| 内容 | 仓库里 | 新机器上 |
|---|---|---|
| `config/keys/` | 不含（.gitignore） | `gen_accounts.py` 生成新身份 |
| `config/system.json` 公钥 | 原机器的公钥 | `gen_accounts.py` 自动改写 |
| `config/chain.json` | 原机器链的合约地址 | 跑 `deploy_contract.py` 后覆盖 |
| `chain/nodes/` | 不含 | `build_chain.sh` 重新生成 |
| `contracts/build/` | 不含 | `compile_contract.sh` 重新编译 |
| `data/`、`logs/` | 不含 | 运行时创建 |

如果你想把原机器的测试身份也带过去，直接复制 `config/keys/` 即可（**不要**再跑
`gen_accounts.py --force`，否则会与 `config/system.json` 里的公钥不一致）。

## 12. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `build_chain.sh` 卡在 “Generating keys” | 用了 macOS 自带 bash 3.2 → 换 `/opt/homebrew/bin/bash` |
| 证书生成报 `v4_req` 相关错误 | 用了未打补丁的上游脚本 → 用仓库内版本 |
| `deploy_contract.py` 连接失败 | 链没起 → 先 `./scripts/start_chain.sh` |
| `solc: command not found` / 权限错误 | 没下载或没 `chmod +x tools/solc` |
| 端口被占用 | 先 `./scripts/stop_services.sh`；改端口要同时改 `config/system.json` 与链端口 |
| 页面 8400 打不开 | `./scripts/start_services.sh` 没跑完，或 8400 被占用 |
| Python 导入 SDK 报 `collections` 错误 | Python <3.10，或没有走 `src.common.compat` 的 shim |
| `chain/bin/fisco-bcos` 无法执行 | 下载了错误平台版本 / macOS 需要 `chmod +x` |
| Apple Silicon 上 solc 报 “Bad CPU type” | 没装 Rosetta：`softwareupdate --install-rosetta` |

## 13. 停止与重置

```bash
./scripts/stop_services.sh      # 只停业务服务，链保留
./scripts/stop_chain.sh         # 停 5 个链节点
./scripts/reset_local_state.sh  # 归档 data/，不动链上证据
```

彻底重建链（**会删除本地区块与历史证据**，先备份 `chain/nodes/`）：

```bash
./scripts/stop_chain.sh
rm -rf chain/nodes
# 重新执行第 7、8 步
```

## 14. 安全提醒

- 仓库是公开的，但 `config/keys/`、`chain/nodes/` 等私钥材料**不在仓库中**；
  自己生成的密钥也不要提交。
- 本实验的签名、证书、链账户全部是测试用途，不能用于真实电力系统。
- Web 服务只监听 `127.0.0.1`；不要把 8400/8201/8301 直接暴露到公网。
