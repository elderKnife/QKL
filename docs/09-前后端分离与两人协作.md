# 09 前后端分离与两人协作

## 1. 现状：已经分开

| 层 | 代码 | 运行方式 |
|---|---|---|
| 前端 | `console-prototype/frontend`（Vue 3 + Element Plus + Vite） | 开发：Vite 5173；生产：构建成 `dist/` |
| 后端 | `src/console/service.py`（Flask，BFF/适配层） | 8400，提供 `/api/*`，生产时顺带托管 `dist/` |
| 领域服务 | `src/edge`、`src/vpp`、`src/grid` | 8101–8104 / 8201–8202 / 8301 |
| 链 | FISCO BCOS 5 节点 | 8545–8549 |

生产部署是**同源**（8400 同时给页面和 API），所以没有 CORS，Cookie Session 直接可用；
开发时前端跑 Vite，`/api` 通过代理转到 8400，浏览器仍然认为是同源。

## 2. 本地两人开发怎么跑

### 后端同学（终端 A）

```bash
cd /Users/zyd/PycharmProjects/QKL
./scripts/start_chain.sh          # 首次或链未启动时
./scripts/start_services.sh       # edge/vpp/grid/console
# 或者只调 console 时用热重载：
./scripts/dev_console.sh          # 接管 8400，CONSOLE_DEBUG=1，改 Python 自动重启
```

- `CONSOLE_PORT` 可改端口（默认 8400）；
- 想让别的机器访问：`CONSOLE_HOST=0.0.0.0 ./scripts/dev_console.sh`（注意防火墙/内网安全）；
- 后端改接口后，前端无需重启，Vite 代理会自动转发。

### 前端同学（终端 B）

```bash
cd console-prototype/frontend
npm ci
npm run dev                       # http://127.0.0.1:5173
```

- 页面热更新（HMR）；
- `/api` 默认代理到 `http://127.0.0.1:8400`；
- 只改 Vue/样式时不需要构建 `dist`，也不需要重启 Flask。

### 跨机器（两人不在同一台电脑）

前端机器上：

```bash
cd console-prototype/frontend
VITE_API_TARGET=http://<后端机器IP>:8400 npm run dev -- --host 0.0.0.0
```

浏览器访问 `http://<前端机器IP>:5173`。Vite 代理会把 `/api` 转给后端，
Cookie 仍由前端同源接收，**不需要给 Flask 加 CORS**。

也可以直接 SSH 隧道：

```bash
ssh -L 8400:127.0.0.1:8400 user@backend-host
```

然后前端代理保持默认 `127.0.0.1:8400` 即可。

## 3. 接口契约

- 接口清单、字段说明见 [docs/08-FISCO控制台.md](08-FISCO控制台.md) 第 6 节；
- 前端调用封装在 `console-prototype/frontend/src/api.ts`；
- 后端实现在 `src/console/service.py`；
- **改字段要双方约定**：先改文档/类型，再改后端，最后改前端；
- 错误格式统一 `{error:{code,message,retryable}}`，分页统一 `{items,total,page,pageSize}`；
- 目前是 `/api/...`，如要做长期兼容可加 `/api/v1` 前缀（未做）。

## 4. 前端不想依赖链/后端时

当前没有内置 mock。推荐两种做法：

1. **共享后端**：后端同学在一台机器起完整栈，前端用 `VITE_API_TARGET` 指过去；
2. **MSW mock**：在 `frontend/src/mocks` 里按 `/api` 契约返回固定 JSON，
   用 `VITE_USE_MOCK=1` 在 `main.ts` 启动 worker（需要新增依赖，尚未实现）。

没有后端时，登录、批次列表、详情、日志都可以用固定 fixture 开发；
联调时再切回真实后端。

## 5. 构建与部署

```bash
cd console-prototype/frontend
npm run build          # vue-tsc 类型检查 + vite build，产物 dist/
```

`dist/` 不入库；部署机拉代码后需要构建一次。Flask 的 `/` 和 `/assets/*` 直接托管 `dist/`，
所以生产只需要启动 `src.console.service`（以及 edge/vpp/grid/链）。

## 6. 分工建议

- **前端**：`console-prototype/frontend/**`（页面、组件、样式、`api.ts`）；
- **后端**：`src/console/**` 与 `src/{edge,vpp,grid}/**`（契约、字段、链交互）；
- 共享：`docs/08`、`docs/09`、`config/`；
- 分支：`feat/frontend-*`、`feat/backend-*`，接口变更走 PR 互相 review；
- 提交前：前端 `npm run build`，后端 `python -m unittest discover -s tests`。

## 7. 常见坑

1. **端口**：Vite 5173、console 8400、grid 8301、vpp 8201/8202、edge 8101–8104，不要互相占用；
2. **代理目标**：默认 8400；若后端换了端口，用 `VITE_API_TARGET` 覆盖，不要改死代码；
3. **登录**：Session 存在 Flask 侧，后端重启后需要重新登录；Vite HMR 不影响登录；
4. **Cookie/CORS**：优先用 Vite 代理；直接跨域直连才需要 CORS + `SameSite=None; Secure`，不推荐；
5. **dist 过期**：生产 8400 托管的是 `dist/`，改了 Vue 必须重新 `npm run build`，否则看到的还是旧页面。
