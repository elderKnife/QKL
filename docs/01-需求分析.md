## 2. 本次明确要求的操作（以此为准）

用户为本轮实验划定了硬边界：

1. **四个边缘节点**（第二轮扩展）：`edge-01`、`edge-02` 归属 `vpp-a`，
   `edge-03`、`edge-04` 归属 `vpp-b`，每个 VPP 两个边缘；
2. **每个边缘 10 台终端设备**，共 40 台，由边缘模拟采集；
3. **两个虚拟电网**：`vpp-a`、`vpp-b`；**一个国网平台**：`grid`；
4. 边缘 ↔ VPP **不做区块链**，只做数据通信（本实现含边缘签名、VPP 验签）；
5. VPP ↔ GRID **使用区块链**，但**只保存根哈希**，用于校验；
6. **自动采集**：每 10 秒一轮，提供开始/暂停；
7. **国网指令下发**：设置电压、开机、关机，沿 GRID→VPP→边缘 下行，回执根原路返回并上链；
8. **暂不引入 A1 终端**（300 台设备模拟器）：边缘内置 10 台设备模拟作为替身。

本实现按此边界建设，没有顺手实现 10×30 全量、真实电网协议或真实设备控制。

## 4. 明确不在本实验范围内的内容

| 内容 | 原因 |
|---|---|
| A1 设备模拟器（300 台、10 边缘） | 用户明确“暂时不需要引入 A1 终端”；用边缘内置模拟替代 |
| 真实电网协议、真实设备控制 | 任务书列为后续适配模块 |
| Web 展示、B 的 GRID/VPP 业务数据库 | B 负责 |
| 10 个边缘 / 300 台设备的规模验收 | 留待 A1 接入后做规模实验 |
| 生产级 PKI、TLS 双向认证、跨机部署 | 任务书列为后续/待确认 |
| 性能指标（万条/百条） | 本轮不做性能结论，避免与正确性验证混淆 |

## 5. 对“暂不引入 A1”的处理方式

边缘节点内置 10 台设备的**模拟采集**（`_simulate`，按设备类型生成合理功率，
并受最近一次开/关机、电压指令影响），每 10 秒采集一轮；同时保留
`POST /api/v1/records` 注入接口和 `scripts/feed_records.py` 手动注入脚本。

- 模拟只发生在边缘，**不伪造链上证据**：仍然是先成包、签名、上报、构树、上链；
- 未来接入 A1 时，把 A1 的输出改为 POST 到同一边缘接口，或替换 `_simulate`，其余链路不变。

## 6. 需要导师/B 确认的事项（本轮采用的默认值）

| 事项 | 本轮默认 | 影响 |
|---|---|---|
| 边缘包记录数 | 每边缘 10 台设备、10 条/包 | 第二轮要求 |
| 一条边缘包 ↔ 一个存证批次 | 是 | 与任务书“一包一批”建议一致 |
| 采集周期 | 10 秒/轮，每边缘 10 条 | 第二轮要求 |
| 指令 TTL | 120 秒；电压范围 180–260V | 本实验冻结值，可配置 |
| 根哈希仅为记录 Merkle 根，不含包头/签名 | 是 | 与任务书 §6.3 建议一致 |
| 反馈、转发事件是否上链 | 转发事件**不上链** | 任务书列为待确认，本轮不默认增加 |
| 交易账户由谁持有 | VPP A/B 各自持有业务账户；GRID 为合约 owner | 与任务书“GRID/VPP 分别使用获授权交易账户”的建议一致 |
| 是否使用 Console | 否，使用 Python 结构化适配层 | 避免解析 Console 文本 |
| 反馈/指令的业务标签 | 未实现 | 待确认后再做 |
